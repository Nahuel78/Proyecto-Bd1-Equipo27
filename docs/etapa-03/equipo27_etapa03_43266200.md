## 1\. Aporte realizado

Describir brevemente las actividades realizadas durante esta etapa.

- Diseño, estructuración y codificación del script DML (Data Manipulation Language) para la inserción de datos iniciales en la base de datos bajo el motor de Microsoft SQL Server (T-SQL).  
- Población integral de las tablas del sistema (Provincia, Localidad, Proveedores, Clientes, Categorías, Géneros, Productos, Depósitos, Ventas, Detalles, Comprobantes y Medios de pago) con datos coherentes y normalizados.  
- Adaptación y verificación de la sintaxis orientada a SQL Server (incorporación de bloques de lote GO, tipos de datos BIT y manejo de identificadores IDENTITY).

## 2\. Decisiones en las que participé

Indicar decisiones relacionadas con el dominio, alcance o reglas de negocio.

- Definición del orden de inserción lógico de los datos para respetar estrictamente la integridad referencial (por ejemplo, cargar primero las provincias antes que las localidades, y las categorías/géneros antes que los productos).  
- Selección de registros de prueba representativos para validar las restricciones del modelo (como validaciones de correos electrónicos con @, precios y stocks mayores o iguales a cero).

## 3\. Problemas o dificultades identificadas

Describir dificultades encontradas durante el desarrollo.

- Incompatibilidades de sintaxis al adaptar scripts o restricciones estándar a las particularidades del motor Microsoft SQL Server (manejo de autoincrementales y tipos booleanos).  
- Complicaciones iniciales con la interfaz web de GitHub al intentar estructurar las carpetas y subir o gestionar el archivo de código fuente .sql.

## 4\. Soluciones o propuestas realizadas

Explicar brevemente cómo se resolvieron o propusieron resolver las dificultades.

- Modificación de los comandos de creación y carga utilizando la sintaxis nativa de T-SQL (como IDENTITY(1,1) y BIT) y particionamiento del código con instrucciones GO.  
- Implementación del método de creación directa de rutas en GitHub (carpeta/archivo.sql) para asegurar una correcta organización del repositorio sin errores de subida.
